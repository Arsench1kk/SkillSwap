# SkillSwap — сценарий проверки сайта и тестовые данные

Сайт: https://skillswap-blue-chi.vercel.app/

Это руководство разделяет безопасную проверку production-сайта и сценарии, которые пока доступны только в локальных E2E-тестах. Production-база новая; события там помечаются `rehearsal`. Это не означает, что сайт готов принимать реальные обращения.

## Важно перед тестом

- Не вводите настоящие имена, телефоны, Telegram-аккаунты, ссылки на личные файлы или сведения о реальных учебных задачах.
- Успешные отправки формы записываются в базу и автоматически не удаляются. В интерфейсе нет функции очистки тестовых записей.
- Не запускайте `npm run db:seed:rehearsal`, `npm test` или `npm run e2e` из текущего `apps/web`, пока не проверили `DATABASE_URL`: Vercel CLI скачал переменные Neon в `.env.local`, и команды могут обратиться к удалённой базе, а не к локальному Docker.
- Не отправляйте фиктивный safety report на production: у команды ещё нет готовой операторской очереди обработки отчётов.
- До реального пилота команда должна утвердить privacy/consent и safety escalation, назначить ответственного и подключить обработку просроченных отзывов.

## Что сейчас можно проверить прямо на production

Без записи данных:

1. Откройте главную страницу и проверьте объяснение сервиса и переходы «Request a session», «I can help others» и Privacy.
2. Откройте `/request` и проверьте поля, формат времени `Almaty time`, доступность с телефона и работу клавиатурой.
3. Откройте `/mentor/join`, изучите анкету и consent.
4. Проверьте `/privacy` и отображение на ширине 360 px.
5. На production `/dev/kit` намеренно возвращает 404: дизайн-кит только для разработки.

Отправка L1 или M1 создаёт постоянную запись. Делайте это только если команда сознательно проводит внутреннюю репетицию и готова оставить тестовые записи в базе.

## Сквозной путь ученика: E0 → L1 → L2

### Тестовые данные L1

Используйте только как синтетический пример. Даты ниже приведены для проверки 21 октября 2026 года; если тестируете позже, сдвиньте их, сохранив интервалы и правила.

| Поле | Тестовое значение |
|---|---|
| Область | STEM |
| Что не получается | `FAKE REHEARSAL: In Google Sheets, my line chart stops at the old rows after I add weekly data. I need to include the new rows before a statistics assignment.` |
| Что уже пробовал | `FAKE REHEARSAL: I checked the chart data range and refreshed the sheet. New rows are still missing.` |
| Срок | 28 октября 2026 |
| Окно 1 | 23 октября, 18:00–19:00, Almaty time |
| Окно 2 | 24 октября, 17:00–18:00, Almaty time |
| Чем может поделиться | `FAKE REHEARSAL: I can show basic CapCut trimming and captions.` |
| Контакт | Только handle тестового аккаунта, контролируемого командой. Пример `@skillswap_rehearsal_learner_001` — лишь фиктивная строка для формы, не гарантированно свободный аккаунт |
| Consent | Отметить только для фиктивного теста после прочтения текста на сайте |

Ожидаемый поток:

1. На главной нажмите «Request a session».
2. Заполните поля и отправьте заявку.
3. Убедитесь, что открылся личный URL `/request/<token>` и показано состояние ожидания.
4. Не публикуйте и не пересылайте token-ссылку: она персональная.
5. До отмены можно проверить изменение срока и доступных окон. Для отдельной проверки отмены нужна другая заявка: отменённую заявку нельзя использовать для остальных сценариев.
6. Проверьте ссылку Report a problem визуально; не отправляйте fake safety report в production.

### Проверки отказа по eligibility

В отдельном чистом сеансе браузера проверьте:

- `Task area = Other`: сайт должен объяснить, что с этой областью помочь может не получиться; запрос не должен становиться обычной заявкой.
- Срок дальше 14 дней: ожидается сообщение о неeligible-заявке, а не обычная страница ожидания.
- Пустые обязательные поля или одинаковые/обратные интервалы времени: inline-ошибки, введённый текст остаётся на месте.

Не повторяйте много отправок подряд: на публичных формах включён rate limit.

## Отдельный путь ментора: M1

Если команда разрешила создать ещё одну rehearsal-запись, заполните анкету только вымышленными данными:

| Поле | Тестовое значение |
|---|---|
| Имя | `FAKE REHEARSAL MENTOR` |
| Область | STEM |
| Тема | `Google Sheets chart ranges and formulas` |
| Тип подтверждения | Link |
| Подтверждение | `https://example.invalid/skillswap-rehearsal-proof` |
| Доступность | Два будущих окна по одному часу в Almaty time |
| Контакт | Только handle тестового аккаунта, контролируемого командой. Пример `@skillswap_rehearsal_mentor_001` — лишь фиктивная строка для формы, не гарантированно свободный аккаунт |
| Consent | Отметить для фиктивной анкеты после прочтения текста |

Ожидаемый результат — сообщение об отправке анкеты. Это не означает, что навык проверен или ментор подтверждён: ручная верификация и операторская панель не доступны через публичный интерфейс.

## Сценарии, которые пока нельзя пройти целиком на production

| Этап | Что нужно для теста | Текущее ограничение |
|---|---|---|
| M2 — mentor brief | Валидная персональная brief-ссылка с назначенным ментором и заявкой | Публичной формы/операторской панели для создания матча и выдачи этой ссылки нет |
| L3 — ученик подтверждает время | Запрос, ручной match и предложение времени | Публичный операторский flow отсутствует |
| L4 — страница сессии и Meet | Подтверждённый match, запись session и приватная session-ссылка | Сессия не создаётся публичным flow |
| L5 — рейтинг | Завершённая сессия и rating-ссылка | В тестовых E2E фикстурах ссылки создаются напрямую в БД; production-интерфейс их не выдаёт |
| X2 — отправка отчёта | Доступная token-страница и действующая команда обработки | На production не отправляйте искусственные жалобы; сначала настройте операционный процесс |

Для этих экранов используйте имеющиеся Playwright E2E-сценарии на отдельной локальной тестовой БД. Они создают фикстуры напрямую и проверяют состояния без публикации личных данных. Перед запуском убедитесь, что `DATABASE_URL` указывает на локальный Postgres (обычно порт `5433`), а не на Neon/Vercel.

## Набор сценариев локального QA

1. L1: валидная STEM-заявка → L2 ожидание.
2. L1: некорректный ввод, unsupported category и срок вне 14 дней.
3. L2: обновление времени/срока; отдельная фикстура для отмены.
4. M1: валидация, сетевой сбой с сохранением текста, успешная отправка.
5. M2: unanswered → propose; смена предложенного времени; decline → повторный ответ; withdraw; learner cancelled; expired; network failure.
6. L3: подтверждение предложенного времени, отказ и восстановление после отзыва ментора.
7. L4: рендер плана сессии, действие Meet и сообщение «не могу прийти».
8. L5: полная отправка, частичная отправка и продолжение, завершённое окно, повторно отправленная оценка.
9. X1/X2: недействительная ссылка и доступность формы отчёта; fake report отправлять только локально.
10. На каждом маршруте проверить ширину 360 px, клавиатурную навигацию, видимый focus и отсутствие горизонтальной прокрутки.

## Как безопасно запускать локальные тесты

Из `apps/web` сначала проверьте хост в `DATABASE_URL` локальной конфигурации. Он должен быть `localhost`/`127.0.0.1` и порт `5433`, а не удалённый Neon host. Затем используйте локальный Docker Postgres и команды из README:

```sh
docker compose up -d db
npm run db:migrate
npm run db:seed:rehearsal
npm test
npm run e2e -- --workers=1
```

Rehearsal seed создаёт только ограниченные фиктивные записи и сам по себе не выдаёт готовые ссылки для M2/L3/L4/L5. Не запускайте этот блок с Vercel-переменными.

## Что считать результатом проверки

Запишите для каждого сценария: дату и время теста (Almaty), ширину экрана, маршрут/состояние, ожидаемый и фактический результат, ошибку/скриншот и то, какие фиктивные записи были созданы. Не записывайте token целиком, контакты, имена реальных людей или свободный текст из личных обращений.
