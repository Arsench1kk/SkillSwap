## Что прочитать агенту

1. Корневой `AGENTS.md` и обязательные пять документов в указанном там порядке.
2. [PLAN.md](PLAN.md) — этапы G0/G1, точное владение файлами, зависимости и приёмка.
3. [DECISIONS.md](DECISIONS.md) — что ещё должна решить команда; не додумывать.
4. Своё задание из таблицы; [аудит](AUDIT_2026-11-04.md) — основание работ.

Если пользователь не назвал участника/задание, уточнить его **до изменения кода**.
Не определять личность по `git config user.name` и не брать соседнее направление
без явной передачи. Перед реализацией назвать D-код, этап, свои файлы и зависимости.
Арсен — участник, заказавший этот план; это не означает, что любой агент работает
от его имени по умолчанию.

## Порядок старта

**Документация опубликована отдельно от локальных изменений приложения.**
Аудит проверял локальный `5e661d5` поверх GitHub `8cbfb90`; эти прикладные изменения
не включены в публикацию плана. Проверять реальную ветку/коммиты, не предполагать,
что локальный SHA уже доступен команде. Не применять рекомендации аудита как патч
без проверки фактического кода.

G0 ещё не завершён: Андрей сначала готовит общий PR форматирования; Арсен
согласует общую базу и выделяет модули из большого файла кабинета. Остальные пока
готовят свои спецификации/матрицы состояний и тестовые сценарии по PLAN.
После объединения G0 ветки создаются из одной актуальной `main`. Не стартовать
шесть параллельных переписей `prototype-app.tsx`.

Затем закрываются зависимости G1: согласованные screen IDs, поля, состояния,
права, события и контракты. Открытое решение блокирует зависимую часть, а не всю
работу исполнителя. Не создавать fake persistence, вымышленные профили в рабочей
выдаче, новые события или модерацию «по своему усмотрению».

## Общие файлы и передача изменений

- **Арсен / D1:** общая схема, миграции/Drizzle metadata, auth/права, общие
  контракты и оболочка. Остальные передают ему запросы на изменения базы/контрактов.
- **Андрей / D6:** строки/переводы, общие UI/config, package/lockfile, CI и общая
  тестовая инфраструктура. Ключи строк добавляются заранее через его PR.
- **Руслан, Амир, Нурлан, Тогжан:** свои feature-каталоги, серверная логика и
  тесты согласно точной матрице PLAN. Чужой сервис вызывать по контракту, не
  копировать SQL или правила, чтобы избежать зависимости.
- G0-исключения координируются до edits. После передачи модуля у него один владелец.
  Спорную границу согласовать с Арсеном и владельцем, не обходить запрет.

Работать в своей ветке, отправлять небольшие PR и получать обновления `main`.
Не перезаписывать чужую работу и не разрешать конфликт слепым выбором всей своей
версии. Каждый пишет тесты своей логики; Андрей не заменяет тестирование автора.

## Что участнику написать своему агенту

Пример для Руслана; заменить имя и код на свои:

> Я Руслан, моё направление D2. Прочитай AGENTS.md и docs/launch/README.md,
> затем PLAN.md, DECISIONS.md и tasks/D2_RUSLAN_LEARNER.md. Проверь, завершён ли
> общий этап G0. Назови мои разрешённые файлы и незакрытые зависимости. Выполняй
> следующий доступный небольшой шаг моего задания; чужие файлы не меняй.

Перед новой сессией получить актуальный репозиторий. Для существующей локальной
копии сначала проверить `git status`: при несохранённой работе не делать reset
или перезапись ради обновления. После обновления начать новую сессию агента или
явно попросить его перечитать инструкции. Наличие файлов — помощь в координации,
а не гарантия отсутствия ошибок или замена проверки PR.

## Источники поведения файлов инструкций

Использованы стандартные файлы проекта: Codex читает [AGENTS.md по иерархии

Code поддерживает [импорт AGENTS.md из CLAUDE.md](https://code.claude.com/docs/en/memory#share-one-file-with-other-coding-tools).
Корневые правила не дублируются двумя независимыми списками; app-specific правила
также импортируются через `apps/web/CLAUDE.md`.
