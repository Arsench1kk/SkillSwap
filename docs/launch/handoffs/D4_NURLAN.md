- **Автор:** D4 / Нурлан. **Адресаты:** D1, D2, D5, D6.
- **Проверено:** 10 ноября 2026. **Статус:** open / Draft, не merged.
  **PR:** [№8](https://github.com/Arsench1kk/SkillSwap/pull/8).
  Доставка записи в main — отдельный docs PR, ожидает объединения.
- **Ветка:** `codex/nurlan-sessions-a05`. **Head прикладного кода:**
  `75d6652265b67687b96953f56a5de944bc71faa9`.
  A05 отдельно: `1627c08`; expiry: `75d6652`.
- **Base:** main `601efb5` (получена актуальная документация команды). Draft PR D1 №1–6 не объединялись в эту ветку.
- **Контракт:** `apps/web/src/domain/rating-page.ts` → `isRatingWindowOpen`
  принимает `{ endsAt, completionState }` и необязательный `now`.
  Допуск только completed, с записанным endsAt, в интервале от endsAt до
  endsAt + 2h включительно. Страница и `app/api/rating/route.ts` используют
  состояние встречи; ранняя запись возвращает существующий `link_unavailable`.
  Внутри текущего дерева все потребители обновлены.
- **Expiry:** `apps/web/src/domain/expire-feedback.ts` →
  `expireUnansweredFeedback(pool)` сохраняет сигнатуру и возвращает число
  действительно обновлённых строк. Меняет только отсутствующие ответы с reason
  incomplete на no_reply; остальные причины и заполненные ответы сохраняются.
  Работает только completed с endsAt строго ранее now() - 2h. Повтор без новой
  работы возвращает 0. SQL выполняется одним statement.
- **Действие получателя:** D5 не выдавать ранний rating-link как разрешение
  оставить отзыв; completion и время должны иметь согласованный источник.
  D6 учесть новый смысл счётчика jobs и запустить интеграционный тест на
  отдельной PostgreSQL: `SKILLSWAP_D4_TEST_DATABASE_URL=<test database>` и
  `npm test -- src/domain/expire-feedback.integration.test.ts` из apps/web.
  Тест использует временные таблицы и rollback, не мигрирует рабочую БД.
  D1/D2 учитывать сигнатуру predicate при будущей интеграции. Не считать этот
  код уже доступным из main.
- **Проверки:** lint, typecheck, 58 Vitest тестов успешно; 9 DB-тестов пропущены
  без явного подключения. Из них новый SQL-тест expiry отдельно успешно выполнен
  через временный pg-adapter в PGlite 0.5.15 (Apache-2.0), девять fixture-строк,
  включая partial, все незавершённые состояния, null end, точную границу и retry.
  Это реальный SQL engine, но не проверка pg-протокола, production migrations или
  конкуренции полноценного сервера. PGlite установлен только в /private/tmp,
  не является зависимостью приложения. TypeScript/ESLint проверяют и PG-тест.
- **Ограничения:** Настоящий PostgreSQL,
  scheduler и E2E не запускались. Общий известный долг форматирования 26 файлов
  не исправлялся. UI и строки не менялись. Схема, package/lockfile, чужие
  endpoints не менялись. Гонка записи отзыва и expiry требует отдельного
  PostgreSQL-прогона; общий scheduler D6 и перенос entrypoint в G0 не выполнены.
  R07/R11, exact-session token A04 и полная цепочка создания встреч не закрыты.
  Публикация feature-ветки выполнена; документация передачи вынесена
  в отдельную ветку `codex/nurlan-d4-handoff`, ожидает docs PR/объединения в main.
