## D4-H002 — конкуренция отзыва и expiry на PostgreSQL

- **Автор:** D4 / Нурлан. **Адресаты:** D1, D5, D6.
- **Проверено:** 14 ноября 2026. **Статус:** дополнение Draft
  [PR №8](https://github.com/Arsench1kk/SkillSwap/pull/8), не merged.
  Документация доставляется отдельным [PR №9](https://github.com/Arsench1kk/SkillSwap/pull/9),
  публикация в main ожидает его объединения.
- **Ветка:** `codex/nurlan-sessions-a05`. **Коммит тестов:**
  `c146e43e9bd412875d425290606364de7a2a2d77`.
  Base тестов — предыдущий head №8 `de5b05bbec9c91787bf1ae106c5b25f2e47a2c3f`;
  новые feature-зависимости не подключались. Изменения D2 из main 435344c
  пока не включены в эту ветку; тест не вызывает learner-код.
- **Контракт:** приложение и API не менялись. Новый собственный тест
  `apps/web/src/domain/rating-concurrency.integration.test.ts` вызывает настоящий
  POST rating, Drizzle и expiry SQL через независимые PostgreSQL-соединения.
  Через pg_blocking_pids подтверждает реальное ожидание блокировки в обоих порядках.
  Проверяет rating commit → expiry, rating rollback → expiry, expiry commit → rating.
  Сохранённые ответы не теряются; пропуски становятся no_reply; повтор expiry — 0;
  при откате нет сохранённого ответа/тестового события; поздний POST возвращает 410.
- **Изоляция/метод:** только явный `SKILLSWAP_D4_TEST_DATABASE_URL`;
  уникальная схема d4_race_<uuid> с минимальными таблицами/ограничениями,
  два рабочих соединения и наблюдатель. Таймауты запросов/блокировок заданы.
  finally освобождает барьер, завершает транзакции и удаляет только свою схему.
  Для воспроизведения нужна отдельная тестовая БД и право CREATE SCHEMA.
- **Ограничения:** auth/token/limiter/contact и event writer заменены тестовыми
  адаптерами. Event writer выполняет настоящий SQL внутри route transaction,
  затем позволяет паузу или ошибку; это проверка атомарности route, не полного
  recordEvent. Часы допуска POST контролируются отдельно, чтобы без реального
  ожидания двух часов воспроизвести уже допущенный запрос, задержанный до expiry.
  Не проверяет синхронизацию часов серверов, реальные миграции, всю event-schema,
  scheduler, произвольное число участников или все возможные deadlocks.
- **Проверки:** typecheck, lint, Prettier нового теста, diff-check прошли.
  На временном PostgreSQL 18.6: три новых конкурентных теста + существующий
  expiry SQL тест — 4 passed. Общий Vitest с D4 TEST_DATABASE_URL и без DATABASE_URL:
  62 passed, 8 остальных DB-тестов skipped. Production/рабочая БД не затронуты.
  PostgreSQL установлен только в /private/tmp через embedded-postgres
  18.6.0-beta.19 (MIT), приложение не получило новых зависимостей/миграций.
- **Действие получателя:** D6 включить оба D4 integration-файла в отдельный
  PostgreSQL-прогон через SKILLSWAP_D4_TEST_DATABASE_URL. D1/D5 учитывать D4-H001:
  эти сценарии подтверждают текущие блокировки/rollback, не меняют R07/R11.
  G0 форматирование №7 всё ещё не merged; общий CI может остановиться до тестов.
