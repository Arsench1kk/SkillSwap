# D5 — Тогжан — оператор, ручной подбор, жалобы и эксплуатация процесса

**Ответственный: Тогжан.** Код направления: `D5`.

Результат: оператор проводит реальную заявку до встречи разрешёнными
инструментами, без ручного SQL и без автоматического назначения. Команда умеет
проверять навыки, исправлять неудачный подбор и обрабатывать жалобы.

Прочитать документы по AGENTS и P10 (`docs/PROMPTS.md:124`), затем
[план](../PLAN.md), [аудит](../AUDIT_2026-11-04.md), [решения](../DECISIONS.md).
P10 уже разрешает локальный CLI как минимальный операторский инструмент. Новый
web UI требует отдельного утверждённого screen/data spec по R06.

## Работы и порядок PR

1. **Сценарий оператора и доступ.** Описать шаги P10 и необходимые права по R06.
   С D1 реализовать серверный guard и безопасную выдачу/отзыв operator-доступа.
   Role toggle learner/mentor не даёт operator. Никакого hard-coded пароля или
   клиентского `isAdmin`; privileged actor загружается из доверенного контекста.
2. **Очередь заявок и проверка.** Дать оператору получить настоящие заявки,
   посмотреть допустимые приватные данные и поставить eligibility по согласованной
   причине. Команды и события learner-модуля предоставляет D2; D5 оркестрирует
   работу, не дублирует state machine. Список/поиск для оператора специфицировать,
   а не копировать публичный поиск вместе с контактами.
3. **Верификация наставника.** Подключить операции D3 и правила R04: proof,
   pending/verified/rejected, решение уполномоченного оператора. Показ приватного
   proof и контактов только по access matrix. Историю/события оформить по R10,
   новых event names самостоятельно не придумывать.
4. **Ручной подбор и brief.** Оператор выбирает mentor для request, фиксирует
   человеческое решение/причину и создаёт реальный brief/link по существующей
   модели. D2/D3 предоставляют команды своего домена. Проверять актуальное
   состояние/проверку навыка, исключить повторное активное назначение согласно
   R07. Написать ошибки/retry и сценарий замены наставника после отказа.
5. **Ссылки и встреча.** Выдавать/отзывать ссылки по согласованным срокам; raw
   token выдаётся только разрешённому оператору, не в logs/CSV/events. Передавать
   Meet, completion и no-show через сервис D4; не создавать sessions/feedback
   собственным SQL. Для Telegram по текущему продукту оператор копирует и
   отправляет ссылки вручную; автодоставку не добавлять без R11.
6. **Жалобы и модерация.** Довести X2 и обработку реальных reports: запись,
   доступ оператора, следующий шаг, ответственный и срок ответа из R05.
   Не обещать SLA, которого команда не утвердила. После R03 подключить команды
   profile/moderation D3. Статусы очереди и поля resolution требуют spec/миграции,
   а не незадокументированных столбцов. Пользовательский safety text не идёт в events.
7. **Экспорт и журнал.** Экспортировать утверждённые события CSV без PII, отделяя
   rehearsal/constructed/real_pilot. Учитывать append-only corrections,
   missing_reason, template_version и R10 experiment. Нельзя экспортировать
   contact/raw token/free-text reports «заодно». Проверить корректное CSV escaping
   и опасные для табличного открытия значения.
8. **Повседневные процедуры.** Согласовать no-reply/follow-up по R11; реализовать
   operator-действия и необходимые повторяемые задания в своём модуле, D6
   подключает scheduler. Передать D6 runbook: новая заявка, отказ, смена mentor,
   жалоба, отозванное согласие, сломанная ссылка, ошибочная запись и восстановление.
   Нужны инструкции и тесты, не только программные функции.

## Приёмка

- Оператор берёт новую заявку из приложения и доводит до реального session-link
  через свои инструменты, без правки БД; полный путь проверен с D2/D3/D4.
- Обычный пользователь не может читать очереди/proof/контакты, верифицировать
  навык или писать operator actor; отозванный доступ перестаёт работать.
- Отказ/withdraw/replacement, repeat команды и конкурентные назначения не ломают
  согласованность; каждое значимое действие имеет допустимый audit/event.
- Жалоба доступна ответственному, обработка и сообщение пользователю соответствуют
  R05; sensitive details доступны только разрешённым ролям.
- CSV и логи не содержат PII/raw links; rehearsal не смешан с real demand.
- Есть runbook, тесты, проверки PLAN, при UI — все состояния, 360 px/keyboard и
  Impeccable. Новые поля/экраны только после спецификации.
