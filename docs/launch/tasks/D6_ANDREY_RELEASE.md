## Работы и порядок PR

1. **Чистая исходная версия.** Отдельным PR до разветвления исправить только
   обнаруженное форматирование. Согласовать исключительный доступ к этим файлам
   в G0; не менять логику/SQL и не форматировать чужие feature PR потом массово.
   Вернуть полный CI после format step. В составе G0 проверить refactor D1.
2. **Безопасная тестовая инфраструктура.** Test runner и app должны использовать
   одну отдельную локальную/CI БД; явное окружение важнее `.env.local`. Добавить
   проверку назначения перед созданием fixtures/seed, изоляцию и безопасную
   уборку synthetic данных. Не запускать очистку на произвольной DATABASE_URL.
   Поддержать fixtures для auth/ролей/проверенных профилей/нескольких встреч.
3. **CI и release build.** CI проверяет format/lint/typecheck, миграции и все
   unit/integration, production build и E2E; критические DB-тесты не молча
   пропускаются. Развести build/dev/E2E по порядку/артефактам, не удалять `.next`
   или `test-results` пока другая проверка их читает. Исследовать CSS `@theme`
   предупреждение, проверить реальные dev/production стили и сборку с нуля.
4. **I18n-инфраструктура.** Сначала R09/R10: охват языков и выбор языка для server
   rendering, приватной ссылки и auth emails. Поддержать единый typed resolver
   для server/client и согласованное поведение без JS. С D1 согласовать event
   locale/model; UI-язык нельзя записывать напрямую клиентом в event context.
   Добавлять строковые ключи заранее общим PR по заявкам D1–D5.
5. **Переводы и текст.** В каталоге 736 ключей, RU/KK по 345; missing 391 на язык
   включает dev/demo. Выделить утверждённый production-охват, устранить fallback
   там, где обещан перевод, локализовать даты/zone labels/письма через контракт.
   Нужна проверка человеком русских и казахских текстов. Новые продуктовые тексты
   берутся из утверждённого UX, privacy — от ответственного команды; TODO(legal)
   не заменять самостоятельно сочинённой юридической политикой.
6. **Общие UI-примитивы и доступность.** Проверить tokens, focus/labels/contrast,
   tap targets, 360 px, loading/error и покрытие glyphs. Сначала общие primitives,
   исправления feature-экранов возвращать владельцу. Запускать Impeccable critique
   и detector для своих UI-изменений; у остальных требовать их результат в PR.
   Это не разрешение на полный редизайн или новые design tokens без согласования.
7. **Общие сквозные тесты.** Полный путь через реальные сервисы без ручных
   INSERT match/session/feedback: регистрация обеих ролей → профиль → verification
   оператором → поиск → заявка → brief → proposal → confirmation → session →
   completion → rating. Отдельно privacy, две роли, чужие IDs, expiry/revocation,
   две встречи и ошибочные/повторные действия. Существующие fixture-тесты оставить
   для отдельных состояний; они не заменяют эту проверку.
8. **Staging и эксплуатация.** Подготовить отдельные БД/конфигурации staging и
   production, auth/email URL и sender, secret inventory без значений, migrate
   порядок, backup/restore и rollback-runbook. Подключить jobs D4/D5 по согласованной
   cadence и доступам; мониторинг ошибок/отказов без контактов/raw tokens.
   Не добавлять внешнюю analytics-платформу. Проверить доставку тестовых auth-писем
   только в согласованном окружении; audit build не подтверждал её.
9. **Документация и решение о релизе.** Устранить A11 и свести утверждённые R01–R11
   в UX/словарь/ADR/README. Организовать usability из UX §11: 5 учеников и
   5 наставников, сохранить результаты и исправления. Собрать чеклист PLAN с
   доказательствами; владельцы фич закрывают свои ошибки. Не публиковать релиз
   автоматически только потому, что тесты зелёные.

## Зависимости и приёмка

Стартовать сразу с G0, тестовой инфраструктуры и CI; i18n-архитектуру согласовать
до массовой разработки UI. Получать от владельцев PR контракты, строки и tests,
от команды — R05/R09/R10, утверждённую спецификацию и переводчика/редактора.

- CI на свежем checkout проходит целиком, включая E2E и все DB-тесты; миграции
  проверены на чистой и предыдущей БД. Нет обращения тестов к production.
- Успех cross-role теста не зависит от demo-массивов или SQL-вставки бизнес-этапов.
- Утверждённые языки работают на account и private-link страницах и письмах;
  источник языка/формат времени согласован, missing production keys выявляются.
- Общие UI и фичи прошли 360 px/keyboard и проверки дизайна; CSS warnings имеют
  объяснённую причину/исправление и проверку dev/production.
- Есть проверенные staging, почта, jobs, backup/restore/rollback и runbook D5.
- Release checklist заполнен фактами; P1 закрыты, остаточные P2 явно приняты,
  privacy/safety и пользовательская проба завершены. Новые зависимости перечислены
  с версией/лицензией или «нет»; реальные secret values не попадают в Git.
