# SkillSwap: инженерный план (фаза 0 → фаза 1)

Написано в роли техлида. Основа: девять md-файлов из `docs/context/`. Не просмотрены `SkillSwap_A6_Evidence_Appendix.docx` и `Lab6 (1).md`: пороги и владельцы взяты из пересказа в md, перед заморозкой их нужно сверить с оригиналом.

## 1. Решение

Кода для самих экспериментов E1, E2, E3 не нужно. Хватает Telegram, Forms, Sheets и Meet. Код нужен только затем, чтобы эксперимент был честным:

1. Пороги заморожены в файле и закоммичены до данных (`thresholds/frozen_thresholds.json`).
2. Журнал событий проверяется валидатором до любого анализа.
3. Решение по E1/E2/E3 считает скрипт, а не человек после просмотра данных.
4. Контакты отдельно от аналитики (анонимные ID).

Всё это уже есть в репозитории, 35 тестов проходят. Дашборд, приложение, матчинг, платежи: после DP2 и только при «continue».

## 2. Что исправить в плане до старта

| # | Проблема | Почему важно | Что делать |
|---|---|---|---|
| 1 | Тайминг E1/DP1. Второй бриф уходит на день 4, окно ответа 48 ч, значит последние ответы в конце дня 6. DP1 тоже на день 6 | Решение по E3 принимается без полных данных E1 | Сдвинуть DP1 на день 7 или сократить окно ответа до 24 ч |
| 2 | E1: один ментор получает P и S в одной теме | Видит, что это один запрос; ответ на второй зависит от первого. Чередование порядка снимает проблему не полностью | Разные задачи для P и S, либо разные группы менторов. При 8–10 менторах группы крошечные, это записать как ограничение |
| 3 | E1 на выдуманных задачах | Измеряется готовность предложить слот, не готовность реально помочь | В отчёте называть это нижней планкой сигнала |
| 4 | Порог «5 из 10» при 8–10 менторах | 5 из 8 не равно 5 из 10 | Выбрать счёт или долю. Сейчас в конфиге доля (50% и 20%), режим `count` тоже реализован |
| 5 | «Не отрицательная» оценка нигде не определена | G2 нельзя посчитать | В конфиге допущение: оценка 1–5, значение не более 2 по пользе или доверию считается отрицательной. Подтвердить |
| 6 | G2 в A5 считается по завершённым сессиям, в A6 по вернувшимся оценкам | Разные знаменатели дадут разные цифры | Считать по вернувшимся оценкам, а долю неответивших показывать рядом |
| 7 | Обмен (swap) в A6 почти не измеряется. Есть «give-back skill» в брифе S, но нет поля и события | Ядро продукта это бартер, а тестируется только бесплатная помощь | Решить, нужна ли запись о ответной услуге в E3. Если да, добавить поле до заморозки схемы |
| 8 | Бюджет 15 человеко-часов на три эксперимента, верификацию и ручной матчинг | Скорее всего занижен, E2 сам требует до 15 минут на кейс | Пересчитать |
| 9 | N=5 в E3 | «3 из 5» статистически ничего не доказывает | В отчётах только счёт («3 из 5»), без процентов как доказательства |
| 10 | Выборка из курсов команды | Convenience sample, а R1–R3 это только три интервью | Так и писать в выводах |

Монетизация (1 500 KZT) остаётся непроверенной гипотезой, как и написано в документах.

## 3. Фазы

**Фаза 0 (сейчас).** Операционка в Telegram, Forms, Sheets, Meet. Репозиторий: схемы, пороги, валидатор, анонимайзер, шаблоны согласия и безопасности, запросы для анализа.

**Фаза 1 (только после DP2 = continue).** Тонкая внутренняя операторская тулза: очередь запросов, карточки менторов, проверка допуска, статусы, отчёт по G1/G2, ручное исправление и журнал изменений. Предлагаю Django + Django admin (авторизация, роли, CRUD, экспорт из коробки; история через `django-simple-history`), PostgreSQL как источник истины. Решение предварительное, см. ADR-001.

**Фаза 2 (только после повторной когорты).** Закрытое приложение для учащихся и менторов. Видео, платежи, мессенджер остаются внешними адаптерами. Здесь уже уместен Next.js, если нужен публичный интерфейс.

**Фаза 3.** Матчинг по правилам с объяснимыми причинами, затем сравнение с pgvector на размеченных результатах. Платёжный эксперимент после доказанной пользы бесплатных сессий.

## 4. Модель данных

Для фазы 0: лист `events` (только добавление) и закрытый лист `participants_pii`. Поля и значения в `docs/DATA_DICTIONARY.md`. Принципы:

- `data_origin` обязателен (real_pilot, constructed, rehearsal). Rehearsal исключается всегда.
- Пропуск не ноль: `missing_reason` из закрытого списка.
- Исправление это новая строка с `corrects_event_id`, историю не переписываем.
- Контакты не попадают в `events`; валидатор ловит почты, телефоны и @ники в заметках.

Для фазы 1 сущности из `TECHNICAL_ARCHITECTURE_PLAN.md` (Participant, SkillEvidence, LearnerRequest, MentorOffer, Match, Session, Feedback, ExperimentEvent, Decision) подходят без изменений. Я бы добавил в Match причину и итоговое решение человека рядом с рекомендацией, чтобы потом можно было сравнить правила и эмбеддинги.

## 6. Переиспользование open source

Для фазы 0 ничего тяжёлого не берём: стандартная библиотека Python, pytest для тестов. Лицензии ниже указаны по памяти, перед использованием проверять по репозиторию.

| Что | Когда | Лицензия | Цена удаления |
|---|---|---|---|
| Google Forms/Sheets/Meet, Telegram | фаза 0 | сервисы | нулевая |
| PostgreSQL | фаза 1 | PostgreSQL License | низкая |
| Django + admin | фаза 1 (кандидат) | BSD-3 | средняя |
| django-simple-history | фаза 1 | BSD | низкая |
| Postgres FTS/trigram | фаза 1–2 | в составе Postgres | низкая |
| pgvector | фаза 3, после размеченных матчей | PostgreSQL License | низкая |
| Next.js | фаза 2, если нужен публичный UI | MIT | высокая |
| Supabase / Keycloak | только если Django auth не хватит | Apache-2.0 | средняя |
| OpenTelemetry | фаза 2 | Apache-2.0 | низкая |
| Redis, Meilisearch, Jitsi, Kubernetes | не брать | у Redis и Meilisearch лицензии менялись | |

Правило из документов остаётся в силе: каждая зависимость это запись в ADR, версия, лицензия, владелец обновлений и путь удаления.

## 7. Риски

| Область | Риск | Мера |
|---|---|---|
| Приватность | Контакты студентов в Google Sheets, выгрузки, согласия | Отдельный закрытый лист, анонимные ID, текст согласия до сбора, контакт раскрывается только после принятия матча. Проверить требования закона Казахстана о персональных данных |
| Безопасность | Незнакомые студенты встречаются онлайн | Назвать ответственного за эскалацию до E3, шаблон жалобы, правило прекращения |
| Предложение | В какой-то категории нет менторов | Считать покрытие по категориям в E2 |
| Злоупотребления | Фейковые подтверждения навыков, спам, no-show | Ручная проверка proof, лимит заявок, учёт no-show |
| Операции | Один человек на ручной матчинг | Замерять минуты на кейс честно |
| Валидность | Смещение выборки, контаминация P/S, подгонка порогов | Пункты 1, 2, 4 выше и замороженный конфиг |
