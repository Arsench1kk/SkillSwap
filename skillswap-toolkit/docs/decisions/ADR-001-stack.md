# ADR-001: Стек фазы 0 и кандидат для фазы 1

Decision: фаза 0 — Python 3 на стандартной библиотеке (скрипты, тесты на pytest). Для фазы 1 кандидат — Django + Django admin + PostgreSQL. Статус: предложено, не принято.
Date: 2026-10-18
Context: текущий этап — ручная валидация. Код нужен только для замороженных порогов, проверки журнала событий и анонимизации. Документы рекомендуют TypeScript/Next.js для первого реального приложения и допускают Python.
Options considered: (a) TypeScript монорепо с Next.js; (b) Python для скриптов и Django admin для операторской тулзы; (c) низкокодовая платформа поверх Sheets.
Chosen option: Python для фазы 0. Для фазы 1 склоняюсь к (b), но решение зависит от того, что команда реально умеет поддерживать.
Why now: скрипты фазы 0 нужны до старта E1, а выбор языка должен быть один, чтобы не заводить два бэкенда.
Hypothesis or evidence linked: ни одну гипотезу A6 не проверяет; снижает риск искажения данных в E1–E3.
Trade-offs: Django admin даёт авторизацию, роли, CRUD и экспорт без разработки интерфейса, но не годится для публичного UI. Для публичного приложения в фазе 2 возможен Next.js, и тогда появится второй язык.
What would invalidate it: никто в команде не готов поддерживать Python или Django; E1 или E2 показали «weaken/hold» и фаза 1 не начинается.
Rollback or replacement path: скрипты фазы 0 не зависят от фреймворка; логика порогов в одном модуле и переносится на другой язык за день.
Owner: не назначен. По RACI владелец технической архитектуры Руслан, решение за ним.
